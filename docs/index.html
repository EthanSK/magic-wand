How It Works

Turning the wand moves my Mac’s pointer or the Agentic Mouse HUD outline. A Puck.js at the tip reads the rotation and sends it over Bluetooth.

  1. Puck.js

    Espruino JavaScript on the wand reads the gyro and buttons, and decides each button gesture.

  2. Bluetooth

    Short text reports travel over the Puck’s Bluetooth UART link: pointer moves, HUD angles, scrolling and button edges.

  3. Wand Receiver

    A background Mac app filters the motion, posts ordinary pointer, click and wheel events, and sends light updates back to the wand.

  4. Mac Apps

    The HUD runs in Agentic Mouse; Top starts Agent Flow. Agent Flow’s recording notifications turn the light red.

The Puck also advertises as a Bluetooth mouse, but macOS pairing stalled, so the receiver routes mouse reports over the UART link instead.

Small device-code updates go through the running receiver, so the wand doesn’t need reflashing or reconnecting. It lights orange while updating.

Needs

  • Agentic Mouse ↗ Draws the HUD and runs its cards. Wand support is in Ethan’s local build and isn’t published yet.
  • Agent Flow ↗ Records and pastes dictation. The public build accepts its mouse controls; wand input isn’t published yet.
  • Espruino ↗ JavaScript firmware on the Puck.js. Public. The first upload uses the Espruino Web IDE.
Grip Angle

Roll the wand to a comfortable grip: Wand Receiver’s Options → Rotation-independent controls reads gravity from the Puck’s accelerometer, so directions stay upright on screen. Sideways speed also holds as the tip rises, with up to 2× correction.

It’s off by default and still needs a physical check. It can’t read roll with the tip pointing almost straight up or down, and it isn’t full 3D tracking. Wrist training with different grip angles is an idea to study, not a tested benefit.
