# Motion controller monorepo

## Layout and ownership

- `magic-wand/` owns the Puck firmware, native receiver, Wand website generators, tutorials, tests and its component instructions. These files previously lived at the repository root.
- `control-stones/` owns the XIAO Sense firmware, debug viewer, wiring diagram and its component instructions. Previously `prototypes/control-stones`; it is a first-class component.
- `shared/` contains only code actually shared across the repository. Do not pre-emptively extract device-specific implementations.
- `docs/` is the published website. Preserve its URLs; its Wand content is generated by `magic-wand/scripts/`.
- Read the target component's AGENTS.md and referenced development skill before changing it. Wand skills live in the repository root `.agents/skills/`. Do not apply Wand button, HUD or hardware assumptions to other devices.
- Keep all actual skill files in the repository root `.agents/skills/`, shared across harnesses. Do not create `.agents/` or `.claude/` directories in components. Use AGENTS.md directly instead of separate CLAUDE.md files. The root `.claude/skills` is only a compatibility link for Claude's skill discovery, never a second copy. User-requested — 2026-10-24.

## Shared working rules

- Work directly on `main` for this project. Do not create worktrees unless Ethan explicitly asks for one. User-requested — 2026-10-24.
- Commit and push completed, checked work after every natural step. Preserve unrelated staged and unstaged work; never force-push. A commit is not a claim of physical acceptance. User-requested — 2026-10-24.
- Keep all existing sensors supported as new ones are added. Keep device-specific firmware and transports separate; share code only when the same behavior is verified. Do not contaminate the Puck JavaScript when adding Sense or future sensors.
- Save durable user rules here when they apply to every component, or in the owning component's instructions when they are specific. Use Ethan's original wording as closely as possible. Preserve verified historical lessons in the owning component's LEARNINGS.md.
- Run `npm run check` from the repository root before committing: it checks privacy across all components and runs each workspace's checks. Run a component command with `npm run <command> --workspace <component>`.
- This public repository stores sources. Never commit device identifiers, local paths, credentials, receipts, raw logs or private settings. Never flash, reconnect or restart real hardware or installed controller apps from this checkout; use the established private installation workflow for authorized hardware work.
- Preserve device profiles, control-version snapshots and immutable tags. Refactoring paths must not silently change runtime behavior or the published website.

## Project skills

- For Wand device, receiver, integration, publication or hardware work, read [magic-wand-dev](.agents/skills/magic-wand-dev/SKILL.md). Its Wand-specific steps do not apply to unrelated devices.
- Before Wand regression or fragile changes, read [learnings](.agents/skills/learnings/SKILL.md) and the relevant component lessons.
